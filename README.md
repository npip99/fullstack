# Fullstack

This is an example fullstack template, created by Nicholas Pipitone. It includes a Python backend and a ReactJS frontend. The backend uses SQLAlchemy and Alembic for managing SQL.

## Setup

First, you'll want to setup your credentials

```bash
cp ./credentials/credentials.example.toml ./credentials/credentials.toml
# Edit credentials.toml and then add your API Keys
```

Then run the setup script,

```bash
./setup.sh # Supports Ubuntu 24.04 and MacOS
```

## Running

In order to run the backend, just execute

```bash
./run.sh
# In order to run in a GNU Screen, use:
# ./run_bg.sh
```

## Testing

In order to confirm that your installation was successful, you can run the unit tests

```bash
./test.sh # Optional `--verbose` flag to see stdout
```

## Linting

In order to lint (Which will cleanup/edit all files), run

```bash
./lint.sh # Optional `--check` flag to lint without modifying anything.
```

Linting will run:
- `ruff` + `basedpyright` for the Python backend
- `tsc` + `eslint` + `prettier` for the ReactJS frontend.
- `./generate_ts_openapi_types.sh`, in order to ensure type safety between frontend TypeScript and backend FastAPI Pydantic BaseModels.

## Migrations

Alembic is used for PostgreSQL migrations. More information about alembic can be found [here](https://alembic.sqlalchemy.org/en/latest/tutorial.html).

The python file at [./src/database/models.py](src/database/models.py) is what uniquely determines the database schema.

### Creating a new migration

If `./src/database/models.py` changes, a migration must occur. In order to automatically generate a migration script, please run

```bash
alembic revision --autogenerate -m "revision commit"
```

By running this command, a new migration script will be generated at `./alembic/versions`. In most cases, the autogenerated script will work. But, you MUST verify the script, as it may require manual adjustment in order to get a correct migration.

Please note that this migration script is generated by comparing the contents of `models.py` with the state of your PostgreSQL database using the credentials found in `./credentials/credentials.toml`. Ensure that your database is-sync with the checked out branch in order to get the desired migration script.

### Ensuring that a migration script is correct.

First, note that alembic makes it easy to confirm whether or not the schema in `./src/database/models.py` is in sync with your database connection. Simply use `alembic check`.

```bash
(backend) npip99@npip99 backend % alembic check
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
No new upgrade operations detected.
```

By using alembic check, it will connect to the PostgreSQL credentials found in `./credentials/credentials.toml`, and ensure that it is in-sync with `models.py`.

> CAREFUL! Since `models.py` is very expressive, it is possible that `alembic check` doesn't notice the change. Please be thorough in confirming that all `models.py` changes are handled in the migration script.

To ensure that a migration script is correct, please execute

```bash
# Checking the branch
git checkout your-branch
alembic upgrade head
alembic check

# Checking downgrading
alembic downgrade head-1
git checkout master
alembic check

# Checking re-upgrading
git checkout your-branch
alembic upgrade head
alembic check
```

This will help ensure that upgrading works and makes your database in-sync with your branch's schema. And, it ensures that downgrading works. Another cycle will add further certainty that your migration script is correct.

## Deployment on EC2

If you would like to deploy this backend onto a fresh Ubuntu 24.04 EC2 instance, you should follow these steps:

```bash
ssh-keygen
cat ~/.ssh/id_ed25519.pub
# Now: Copy this public key into github's deploy keys, so that you can git clone
git clone git@github.com:npip99/fullstack.git
cd fullstack
vim ./credentials/credentials.toml # Now: Paste your API Keys / follow the credentials.toml instructions, and then exit vim
./setup.sh
./setup_nginx.sh subdomain.domain.tld # NOTE: Optional step; do this for https support on port 443
./run_bg.sh
```
